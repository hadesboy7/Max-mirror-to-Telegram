# MAX Mirror

Зеркало беседы из мессенджера [MAX](https://web.max.ru) в Telegram.

Программа держит открытым веб-клиент MAX, читает указанную беседу и пересылает
её содержимое в один или несколько Telegram-чатов. Направление одностороннее:
MAX → Telegram.

Зачем это нужно: читать беседу из MAX в Telegram, не держа приложение MAX
на телефоне.

## Что пересылается

- Текстовые сообщения, с именем автора
- Фотографии, в том числе альбомы (до 10 снимков)
- Видео
- Файлы
- Аудио и голосовые сообщения
- Стикеры
- Ответы на сообщения — с цитатой исходного
- Правки сообщений, с пометкой ✏️
- Удаления сообщений, с пометкой 🗑

Дополнительно:

- **Снимок беседы по кнопке** в боте — файлом без сжатия, чтобы читался текст
- **QR-код для входа** приходит в Telegram, если сессия MAX слетела
- **Очередь с повторами**: если Telegram недоступен, сообщения не теряются и
  досылаются после восстановления связи
- **Состояние в SQLite**: перезапуск не приводит к потере сообщений
- **Отметка о работе** в журнале раз в 30 минут
- **Предупреждения** о слетевшей сессии и о поломке чтения страницы

## Как это работает

Прямого API у MAX для этой задачи нет, поэтому мост работает через браузер:
Playwright запускает Chromium без окна, держит открытой страницу беседы и каждые
две секунды читает список сообщений из разметки страницы. Новые, изменённые и
удалённые сообщения определяются сравнением двух последних снимков списка.

Найденное сразу записывается в базу SQLite, и только потом отправляется в
Telegram. Доставленным сообщение считается **лишь после подтверждения от
Telegram** — поэтому сбой связи или перезапуск программы не приводит к потере.
У каждого целевого чата своё состояние доставки: если один чат недоступен,
остальные получат сообщение сразу, а недоступному оно будет досылаться
повторно.

Внимательно прочитайте [известные ограничения](docs/LIMITATIONS.md) — у MAX нет
идентификаторов сообщений, и это накладывает принципиальные ограничения на
восстановление после долгого простоя.

## Требования

- Python 3.11 или новее (проверено на 3.14)
- Linux, macOS или Windows (проверялось на Linux и macOS)
- Около 700 МБ на диске под Chromium, который скачает Playwright
- Аккаунт MAX с доступом к нужной беседе
- Telegram-бот (создаётся за минуту, см. ниже)

На сервере с 1 ГБ оперативной памяти работает, но вместе с браузером
потребляет 300–500 МБ.

## Установка

```bash
git clone https://github.com/hadesboy7/Max-mirror-to-Telegram.git
cd Max-mirror-to-Telegram

python3 -m venv venv
source venv/bin/activate          # в Windows: venv\Scripts\activate

pip install -r requirements.txt
python -m playwright install chromium
```

## Настройка

### 1. Создайте Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`
2. Задайте имя бота и имя пользователя
3. Скопируйте выданный токен вида `123456789:AA...`

### 2. Узнайте id чатов

Напишите [@userinfobot](https://t.me/userinfobot) — он сообщит ваш числовой id.

- **Личный чат с ботом** — положительное число. Обязательно нажмите `/start`
  у своего бота, иначе он не сможет вам писать.
- **Группа или канал** — отрицательное число вида `-1001234567890`. Добавьте
  бота в группу и дайте право отправлять сообщения.

### 3. Заполните .env

```bash
cp .env.example .env
```

Минимально необходимое:

```ini
TELEGRAM_BOT_TOKEN=123456789:ваш_токен
TELEGRAM_TARGET_CHAT_IDS=123456789
TELEGRAM_ALLOWED_USER_IDS=123456789
MAX_URL=https://web.max.ru/-70000000000000
```

**`MAX_URL`** — адрес конкретной беседы. Откройте web.max.ru в обычном браузере,
войдите, откройте нужную беседу и скопируйте адрес из строки браузера целиком.

### 4. Несколько целевых чатов

Укажите их через запятую — правка кода не нужна:

```ini
# один чат
TELEGRAM_TARGET_CHAT_IDS=123456789

# три чата: личный, группа, канал
TELEGRAM_TARGET_CHAT_IDS=123456789,-1001111111111,-1002222222222
```

У каждого чата своё состояние доставки в базе. Если один недоступен, остальные
получат сообщение сразу, а недоступному оно будет досылаться с нарастающей
задержкой. Успешным получателям повторно ничего не отправляется.

**Добавление чата позже не вызывает рассылку старой истории** — новый чат
начнёт получать сообщения с момента добавления.

### 5. Получатели и управление ботом — разные списки

| Переменная | Назначение |
|---|---|
| `TELEGRAM_TARGET_CHAT_IDS` | **куда** пересылаются сообщения |
| `TELEGRAM_ALLOWED_USER_IDS` | **кто** может управлять ботом: кнопка «Скриншот чата», `/start` |

Участник целевого чата **не получает** управление ботом автоматически. Пустой
`TELEGRAM_ALLOWED_USER_IDS` означает, что управление запрещено всем — это
безопасное поведение по умолчанию.

## Вход в MAX

Первый вход требует сканирования QR-кода, поэтому нужен один запуск с окном
браузера:

```bash
HEADFUL=1 python bridge_ui.py
```

1. Откроется окно Chromium со страницей MAX
2. В приложении MAX на телефоне: **Настройки → Устройства → Добавить
   устройство**, отсканируйте QR
3. Дождитесь загрузки нужной беседы
4. Остановите мост (Ctrl+C)

Вход сохранится в каталоге `max_profile/`. Дальше мост запускается без окна.

> **Каталог `max_profile/` — это доступ к вашему аккаунту MAX.** Не публикуйте
> его, не копируйте в репозиторий, не передавайте другим. В `.gitignore` он уже
> исключён.

## Запуск

```bash
python bridge_ui.py
```

Первый запуск с заполненной базой пометит всю видимую историю беседы как
обработанную и **не будет** пересылать её в Telegram. Дальше придут только новые
сообщения.

Остановка — Ctrl+C. Мост корректно закроет браузер.

## Автозапуск через systemd (Linux)

```bash
cp examples/max-mirror.service /tmp/
# откройте файл и замените User, Group, WorkingDirectory и ExecStart на свои пути
sudo cp /tmp/max-mirror.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now max-mirror
```

Проверка и журнал:

```bash
systemctl status max-mirror
journalctl -u max-mirror -f
```

Пример службы в `examples/max-mirror.service` содержит разумные значения
перезапуска и защиту от бесконечного цикла рестартов. Пути в нём нужно заменить
на свои.

## База состояния SQLite

Файл `state.db` рядом с программой (путь меняется через `STATE_DB`). Хранит:

| Таблица | Что внутри |
|---|---|
| `messages` | обнаруженные события: автор, текст, вложение, тип (новое / правка / удаление) |
| `deliveries` | состояние доставки **отдельно по каждому чату**: попытки, ошибки, время |
| `window_snapshot` | снимок видимого окна беседы — чтобы после перезапуска продолжить с того же места |
| `meta` | версия схемы и отметка о первом запуске |

Состояния заявки: `detected` → `sending` → `delivered`. При сбое — `failed` и
повтор с нарастающей задержкой (30 секунд, минута, две… до часа). После 20
неудачных попыток заявка переходит в `giveup` и перестаёт держать очередь.

Полезные запросы:

```bash
# что в очереди и по каким чатам
sqlite3 state.db "SELECT chat_id, state, COUNT(*) FROM deliveries GROUP BY chat_id, state;"

# последние ошибки доставки
sqlite3 state.db "SELECT chat_id, last_error FROM deliveries WHERE state!='delivered' LIMIT 5;"
```

> **База содержит тексты и авторов ваших сообщений.** Она исключена из
> репозитория в `.gitignore`. Не публикуйте её.

Размер ограничен: хранится до 20 000 последних событий, старые доставленные
удаляются. Недоставленные не удаляются никогда.

## Тесты

```bash
python tests/test_units.py        # разбор конфигурации, дедупликация, сравнение списков
python tests/test_state_store.py  # база состояния: все переходы, повторы, перезапуск
python tests/test_pipeline.py     # сквозной путь: обнаружение → база → доставка
```

Тесты **не запускают браузер и не обращаются в сеть** — Telegram подменён
заглушкой, поэтому их можно гонять где угодно, ничего никуда не отправится.

Что тестами **не проверяется** (нужен живой браузер и аккаунт): реальная
загрузка вложений из MAX, снимок беседы по кнопке, доставка QR, восстановление
сессии. Эти возможности реализованы, но проверяются только вручную после
установки. Подробнее — в [docs/LIMITATIONS.md](docs/LIMITATIONS.md).

## Ограничения

Обязательно к прочтению: **[docs/LIMITATIONS.md](docs/LIMITATIONS.md)**

Коротко о главном:

- У сообщений MAX **нет идентификаторов**. Восстановление после простоя
  ограничено видимым окном беседы (около 30 сообщений).
- Два буквально одинаковых сообщения от одного человека в одну минуту могут
  быть спутаны.
- Абсолютной защиты от дубликатов не существует: Telegram Bot API её не даёт.
  При неудачном совпадении обстоятельств возможна повторная отправка — так
  выбрано сознательно, потому что потеря сообщения хуже дубликата.
- У сообщений **с вложением** MAX не выводит имя автора — придёт «Кто-то».
- Мост зависит от вёрстки веб-клиента MAX. Если MAX её изменит, чтение
  сломается; мост это заметит и предупредит.
- Один запущенный мост обслуживает **одну** беседу.
- Направление Telegram → MAX реализовано, но **выключено** и слабо проверено.

## Безопасность

Эти файлы и каталоги содержат доступ к вашим аккаунтам и переписку. Они
исключены в `.gitignore` — не добавляйте их в репозиторий вручную:

- `.env` — токен бота
- `max_profile/` — сессия MAX, равнозначна паролю от аккаунта
- `state.db` — тексты и авторы сообщений
- `*.png` — снимки беседы и QR-коды
- `calib_dump.html` — разметка страницы с реальной перепиской
- `*.log` — журналы

Журнал мост пишет в стандартный вывод, и в него попадают **первые 50 символов
текста сообщений**. Если журнал куда-то отправляется, учитывайте это.
